# WASM Quick Tour

WASM interests me because it gives the browser another place to run code without giving up the Web platform. I like the boundary: Rust can hold the data and do the tight loops, while JavaScript still owns events, the canvas, and the animation loop.

The old [Rust and WebAssembly book](https://rustwasm.github.io/docs/book/) is still a useful map, even though it is a legacy guide now. It shows the shape I care about: `wasm-bindgen` exposes a Rust API, `wasm-pack` builds the package, and the browser stays in charge of the user interface.

The [Game of Life project](https://github.com/GarfieldZHU/Aloha.zone.io/tree/master/wasm/rust-wasm/wasm-game-of-life) is a small example of that split. Rust keeps the universe and advances each generation. JavaScript draws the cells on a canvas. The interesting part is seeing a Rust data structure become something I can click and play with in a browser.

## The playground

This is the little playground I like. Click cells to make a pattern, pause it, and reset the world when it becomes too chaotic. The frame counter makes the split visible: the WebAssembly module updates the state, while JavaScript schedules and paints each frame.

My current mental model is simple: WASM is not a replacement for the Web platform. It is a compact place to run the part of a program that benefits from Rust, while the frontend remains responsible for the browser experience.
